# Setup

Open **Manage Language Models** and use **Add Models** for each OpenCode entry you want:

- Console and Go accept a service-account API key directly in the native provider form. VS Code stores the field as a secret. Add another named entry to use another account or key. Create keys in the OpenCode Console at https://opencode.ai/console.
- Console also supports device-code sign-in: run **OpenCode: Add Console Account**, choose a profile ID, complete device authorization and organization selection, then enter the same profile ID when adding the native Console provider entry (leaving the API key empty). An entry API key takes precedence over its profile. Leaving the profile field empty preserves the legacy `default` Console account.
- Go additionally accepts the Console device-code flow from the **OpenCode Go: Manage Connection** menu; Go subscriptions are managed in the Console, so both providers share one account flow.
- **OpenCode: Select Console Profile for Usage and Management** chooses the profile targeted by those commands. VS Code restores it after restart; it does not change the account attached to a native model entry.

Console and Go remain separate providers, and each provider can now have multiple named entries. `opencode.defaultMode` only chooses the provider targeted by generic legacy connection, refresh, and test commands; it does not hide other entries. A service-account key loads the shared public `/models` catalog; a Console device-code profile loads organization-scoped model discovery from `/api/config` with `x-org-id`, and models marked `disabled` in that response are excluded.
After device sign-in, VS Code Secret Storage is authoritative. Token refreshes, organization changes, and sign-out operate only on the session managed by the extension. The extension does not read credentials or sessions from local OpenCode data. If the organization config is unavailable, no Console models are shown.

Reasoning-capable models show a **Thinking** or **Thinking Effort** submenu in the Copilot Chat model picker. The extension derives the choices from OpenCode's live `reasoning_options` metadata when available and maps the selected value to the request format required by that model family. Qwen models can also expose a separate thinking-token budget control.

Inline code suggestions (experimental) are off by default. Enable `opencode.inlineSuggestions` to receive ghost-text completions while typing, with fill-in-the-middle emulated over the gateway's chat-completions endpoint using FIM delimiter tokens. Pick the gateway with `opencode.inlineSuggestionsGateway` (`go` by default, `console` also available; the legacy `zen` value is treated as console) and the model with `opencode.inlineSuggestionsModel`; choose a model with a genuine non-thinking mode — measured on the live gateway, `qwen3.7-plus` (Go) and `qwen3.6-plus` (Console) return zero hidden reasoning, while reasoning-first families stay too slow for ghost text. Requests send a bounded window of document context (10 lines before the cursor, 300 characters after, both configurable), are debounced 300ms, time out after 3s, and are aborted on the next keystroke. Suggestions never appear in the Copilot Chat prompt box unless `opencode.inlineSuggestionsChatInput` is enabled.

**OpenCode: Set Inline Suggestions Model** (also in the Manage Connection menu) lists compatible models ordered cheap-and-fast first, each with a measured badge (for example "★ recommended · measured 1.4s TTFB"). Picking a Console-only model while the gateway is Go switches `opencode.inlineSuggestionsGateway` too, and a "Use a custom model id…" entry keeps any undocumented gateway model reachable. The command only writes settings, so changes apply on the next keystroke without a reload.

For Console and Go, a signed-in refresh treats the account's `/models` response as authoritative and fills omitted fields from the canonical `opencode` or `opencode-go` provider in models.dev. Console and Go share one six-hour, stale-while-revalidate metadata snapshot in VS Code `globalState`. The last successful live result is cached for up to 24 hours under a credential-scoped key; organization-scoped Console configuration is never persisted in that public cache. Request limits reserve context headroom, and only rejected optional parameters or transient 502–504/router failures are retried.

Use **OpenCode: Show Usage** or click the status-bar indicator to inspect inference tokens for the most recently used provider entry. Usage snapshots and catalogs remain isolated by API-key fingerprint or Console profile. The generic **OpenCode: Test Connection (Legacy Key / Active Console Profile)** and **OpenCode: Refresh Models (Legacy Key / Active Console Profile)** commands intentionally target only the command-managed Console/Go key or active Console profile. `opencode.defaultMode` chooses the provider family targeted by these commands (legacy `zen` values are treated as console); when it is Console, **OpenCode: Select Console Profile for Usage and Management** chooses the profile. Native entries are discovered and refreshed by VS Code through **Manage Language Models** and the model picker. `opencode.catalogCacheMinutes` controls normal live-catalog freshness, while `opencode.requestTimeoutSeconds` and `opencode.streamIdleTimeoutSeconds` bound total request time and stalled streams separately. Secret-safe request metadata can be enabled with `opencode.debugLogging`.
